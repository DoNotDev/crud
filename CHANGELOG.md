# @donotdev/crud

## Unreleased

### Minor Changes

- `EntityList` (ui) `deletable?: boolean` (default `true`, `EntityListProps`, owner decision 2026-11-25 F7): `deletable={false}` keeps in-place editing and row selection (bulk edit) and removes the selection bar's Delete, standalone and joined to a parent form alike. For records a list must never delete (shopkb `/routines`: the database refuses deletes, routines are archived from their editor; every delete there failed). Web only: the Expo `EntityList` throws when given, as for `extraColumns` / `actions` / `extend`.
- `EntityList` (ui): `date`, `datetime-local` and `timestamp` fields are edited in their cells (owner decision 2026-11-25 C1): `cellEditFor` maps `date` to the DataTable `date` editor and `datetime-local` / `timestamp` to `datetime`, both with the app's time zone (`getAppTimeZone()`). On `/campagnes` (shopkb) the start, end and delivery dates become editable in the list. Read-only fields (generated, computed, `editable: false`, create-only, role-denied, technical) stay read-only. `cellEditFor(entity, name, viewerRole, referenceData, t, language)` takes the UI language (6th argument).
- Price VAT basis follows the field (owner decision 2026-11-25 V2): a price field declares VAT-inclusive prices with `options.fieldSpecific.vatIncluded: true`; `false` or absent = no VAT claim. The column title adds "VAT incl." (`crud:price.columnTitle`) only for a VAT-inclusive field (`fieldColumnTitle`; was every price column); a value's VAT note (detail view, text form) follows the value's own `vatIncluded`, else the field's (`priceVatIncluded`, `fieldVatIncluded`, new in `@donotdev/core`; was `true` by default, legacy bare numbers included); the form's VAT toggle starts at the field's declaration (`PriceFieldComponent` `defaultVatIncluded`, was checked).
- Option lists sort in the UI language (owner decision 2026-11-25 I3): `EntityFilters` options (declared and data values) and `cellEditFor` reference options use `localeCompare(b, language, { sensitivity: 'base' })`, like the menu (`useNavigationItems`): "Écran" sorts the French way on French pages, the same on the server and the client.

- `EntityList` (ui), admin layout (decisions 2026-11-25 P4-P6, P9, P14b): one `<Section>` with an admin header — the count wording as the title, a plain heading (`titleVariant="heading"`, start-aligned): `crud:list.count`, "64 products" (the query total in server mode); 0 rows "0 products" (an empty collection says `crud:list.empty`, "No products yet", once, in the empty row), loading `crud:messages.loading`, a failed read `crud:errors.fetchFailed`; no separate plural title, so a page that already titles itself ("Products") never shows the name twice; `crud:list.count` in ja / ko / zh now carries the entity name (`{{names}} {{count}}件`); the Add button (primary) at the end — replacing the centred uppercase "BROWSE PRODUCT - FILTERS" / "FOUND 64 OCCURRENCES" Section titles. One toolbar row: search · **Filters** button (badge = active filters, opens `EntityFilters` in a narrow side sheet, one column (`cols={1}`), scrolled by the sheet body; was a collapsible section above the results) … Export · Refresh (labelled) · app `actions`. Checked rows (bulk edit, Delete selected, clear) and unsaved edits ("N unsaved changes · Discard · Save", save failures) show in the DataTable bottom `ActionBar`: nothing is inserted above the table any more. Joined to a parent form: the pending count + Discard sit in the toolbar row (a bottom bar would cover the form's own Save). Empty states: an empty collection shows `crud:list.empty` ("No products yet") + Add; no row for the search / filters shows `crud:list.noResultsFor` ("No results for “x”") or `crud:filters.noResults`, + Clear (search and filters). Columns are sized by field type: image 56px, boolean 72, date 112, timestamp 180 (fits "Nov 19, 2026, 11:46 AM"), select / radio 120, reference 180, rating 104 (5 small stars; they were squeezed to 6px in a 50px column); numbers end-aligned with tabular digits; textarea / richtext on 2 lines; the first `text` field is the row name (min 240px, flexible, pinned at the inline start); price titles carry "VAT incl." (`fieldColumnTitle`). Under 640px rows stack (CSS) and, when the entity declares `listCardFields`, only those fields and the name are shown there (`hideOnPhone`). Editable cells read as text until focused (DataTable). No prop change; `editable` default unchanged.
- `EntityFilters`: text and address fields filter with a "contains" text input (debounced 250ms, `crud:filter.contains` placeholder; was a dropdown of the values in the data); the rating filter has the same visible floating label as the others (was `aria-label` only); every filter takes one grid cell (ranges, dates and years no longer span two columns: no holes); "Clear all filters" is a small link-style button after the active-filter chips, shown only with active filters (was a full-width Clear button). The "any" option of text filters is gone.
- `useCrudPageSize`: default page size `DEFAULT_TABLE_PAGE_SIZE` (25, was 12), the DataTable / Pagination constant of `@donotdev/components` (was a copy).
- Display formatters (`formatValue`): list cells (`compact`) show a price's effective amount only, a discount as a small "-15%" badge (was bold green text with "VAT incl." on up to 4 lines; the VAT note moves to the column title, `fieldColumnTitle` in `@donotdev/core`); the detail view shows the struck-through former price, the amount and its VAT note. Booleans: a check icon in list cells (nothing visible for false, "No" for screen readers), translated Yes / No elsewhere. `select` values with a colour (option `variant`, else built-in statuses) render as a `Badge`; other values stay text. Money in the UI language with standard decimals.
- `image` display accepts the documented `Picture` shape `{ fullUrl, thumbUrl }` (showed "—"): a 40 px thumbnail (`ResponsiveImg`) in list cells, the full image pair on the detail view, a neutral 40 px tile (`ImagePlaceholder`) for an empty image in list cells; `images` uses the same thumbnail and tile. `ImageFieldDisplay` shows "—" for an empty value (was "-").
- `ReferenceFieldComponent`: placeholder `crud:reference.placeholder` ("Select {{label}}"), now present in the crud locales (the raw key "reference.placeholder" showed), and empty text `crud:messages.noResults` (the key Combobox and MultiDropdown fields use); the hard-coded English fallbacks are removed.
- `DateFieldComponent`, `DateFilter`: the date pickers take the UI language and their labels (calendar button, load error) from the component locale `@donotdev/ui` provides (`dndev:datePicker.*`); the fields no longer pass `locale` / `calendarErrorLabel` / `openCalendarLabel` (one source). `NumberFieldComponent` / `CurrencyFieldComponent` format in the i18n `language` (set during the server render and hydration pass); they fell back to `navigator.language` (a different text on the server and the client: hydration mismatch).
- `EntityFilters`: one pending timer per typed filter ("contains" text and range min / max share it): "Clear all filters" cancels them all and resets the range drafts and slider positions, a range field's clear cancels its own (a min typed less than 250 ms before Clear all set its filter again after the clear; the range inputs kept showing the cleared values).
- `CrudCard` footer: formatted values that are elements (status badge, check icon, discounted price) render between separators (a string join printed "[object Object]").
- `useEntityForm` (so `EntityFormRenderer`) validates `onTouched` by default (was `onBlur`; the option's JSDoc said `onSubmit`): a field's first error shows when the user leaves it, then the field re-validates on every change, so the fix clears the error while typing. With `onBlur` a corrected field stayed red until it was left again. "Reward early, punish late" (Smashing Magazine, inline validation; NN/g error guidelines; React Hook Form `mode`). `mode` stays overridable. The invalid submit still focuses the first invalid control in DOM order and scrolls it into view (`shouldFocusError: false` stays: the form's own focus skips hidden / disabled controls and reaches composite fields, React Hook Form's follows registration order and needs a focusable ref).
- `cacheStored(collection, row)` on a row no cache of the collection knows is an insert: the document cache is set, the row is appended to every cached list and `total` is bumped, as `add` does. It did nothing for unknown rows (a row from an RPC that created it never showed up). A row already cached (document cache non-null, or in a cached list) is replaced as before.
- `useCrudDoc(entity, id)`: one document, reactive to the shared cache. Every edit, delete (optimistic or confirmed) or subscription write re-renders it. `EntityDisplayRenderer` (ui, expo) uses it: detail views no longer go stale after an edit.
- Removed `useCrud().data` (always `null` since 0.1.x). Read documents with `useCrudDoc` or `get()`.
- Filters: `select` / `radio` / `multiselect` / `reference` filters match exactly (was substring: `toner` matched `toner_pad`), any-of on arrays (OR within a field, AND across fields). `EntityFilters` offers them as multi-selects (state: arrays; a string state still matches). Reference fields (`filterType: 'reference'`, was `'text'`) filter by id with the referenced documents' labels. Option counts/availability are per array item; chips show option / reference labels.
- `field.filter.wildcard` (`FieldFilterConfig`, `@donotdev/core`): a stored value meaning "every option" (e.g. `skinTypes: ['all']`), never offered as a choice, matches any selection. `matchesFilter` takes the field's `filter` as 4th argument (`applyFilters` passes it).
- URL sync of filters: only entity-collection keys (custom `filterKey` states never touch the URL; `useCrudFilters` / `EntityFilters` `urlSync` opt in/out, store `setFilterUrlSync`); re-read on back/forward, navigations and mount (`syncFiltersFromUrl`); option fields as repeated params read back as arrays, values percent-encoded (commas safe); only the entity's own `f_*` params rewritten; router history state and hash kept; a pending write is dropped when the page changed.
- `EntityList` / `EntityCardList` (ui) pass the viewer's role to `EntityFilters`: admin-visibility fields were filtered as `guest`, so admin lists showed an empty filter panel.

### Patch Changes

- `AvatarFieldDisplay` / `ImageFieldDisplay` `size` sizes the avatar (owner decision 2026-11-27 T2, `docs/decisions/2026-11-27-accordion-a11y-perf-dead-classes.html`): `sm` / `md` 48px (`--touch-target`), `lg` 64px, as inline width / height. It mapped to `size-touch` and `h-16 w-16`, classes no CSS defines, so every size rendered the Avatar's 32px default. Avatars shown through these displays get bigger.
- `FormLabel` (ui) turns `--destructive` on a field in error: it sets `data-state="error"` (Label.css). It added Tailwind `text-destructive`, which no CSS defines: the label never changed colour.
- Dead Tailwind classes removed, no visual change (owner decision 2026-11-27 T3, `docs/decisions/2026-11-27-accordion-a11y-perf-dead-classes.html`): `TextFieldDisplay` (`truncate`; `truncate` / `maxLength` still cut the text), `RichTextDisplay` (`prose-sm max-w-none`; `prose` kept).
- URL-synced filters re-read the URL in a microtask after a history change, not inside it. The Navigation API fires `currententrychange` synchronously in `history.pushState`, which Next.js calls in a `useInsertionEffect`; the store update there made React log "useInsertionEffect must not schedule updates" on every client navigation once a filtered list had been opened.
- `CheckboxFieldDisplay` and `BadgeFieldDisplay` show the translated Yes / No (`crud:boolean.yes` / `no`, was the missing key `common.yes`) and the documented "—" for an empty value (was "-") (owner decisions 2026-11-25, `docs/decisions/2026-11-25-admin-ui-leftovers.html` O3).
- List thumbnail size in one place: `LIST_THUMBNAIL_SIZE` (40px, `components/DisplayThumbnail.tsx`), used by the image field's compact display and `ImagePlaceholder`. Undefined `--radius-sm` / `--radius-lg` (drawn square) replaced by the role token of what each element is: `--radius-surface` for the image display's thumbnails and full image, `ImagePlaceholder`, the file / document / image drop zones, the map field frame and the image viewer preview; `--radius-interactive` for the colour swatch (like ColorPicker swatches), the image field's drag handle and remove button, and inline `code` in `RichTextDisplay` / `TiptapEditor`; `--radius-full` for MultiInputText value chips (like `Tag`). These corners were square; they now follow the theme's roles. `DisplayThumbnail` (the card and detail image) uses `--radius-surface` too, as its placeholder and the ImageGallery thumbnails (was `--radius-md`, the same 12px under the default theme, but not the surface role a theme can change).
- `EntityList` (ui): a failed read shows an error state, not an empty table. The results title said `crud:errors.fetchFailed` (was `Found 0 occurrences`); it now shows no title, the box's own title says it once (as the detail view). The shared load-error state replaces the table (`CrudLoadError`, owner decision 2026-11-25 E1, `docs/decisions/2026-11-25-admin-ui-leftovers.html`): title `crud:errors.fetchFailed`, a translated reason from the error code (`dndev:messages.networkError` for `unavailable` / `deadline-exceeded` / `timeout`, `forbidden` for `permission-denied`, `unauthorized` for `unauthenticated`, `serverError` for `internal`, else `messages.error`) and a `dndev:routeError.tryAgain` retry (refetch). Never the error's own message ("Request failed." in English): the raw error goes to the console. Same for the list joined to a parent form (`useChildRows` `error`) and the detail view (`EntityDisplayRenderer`, which gains Retry: `useCrudDoc` `refresh`), and the card grid (`EntityCardList`: it showed the raw message under its own heading; Retry: `useCrudCardList` `refresh`). The reason mapping is `loadErrorReasonKey` (`@donotdev/core`), shared with `@donotdev/expo`. The list hook's `error` was ignored.
- `assertCanAccess` error message and JSDoc: the base fields `defineEntity` adds do not count at their default visibility (see `hasRestrictedVisibility`, `@donotdev/core`).
- `EntityList` (ui): a price column sorts on the price its cells show, the discount applied (`sortValue` from `effectivePrice`), also on extension columns. It sorted on the formatted text (EUR in fr-FR, VAT label, discount clue), which is no number on an English page: `12,5 €` before `12,19 €`. The price display (discounted price) uses `effectivePrice` instead of its own copy of the formula.
- `EntityList` (ui): list columns sort on the value they show (a reference on its label, a select on its translated option, a date chronologically), as the DataTable now sorts natively (`@donotdev/components`); `extraColumns` sort on their text too. The columns no longer set `sortable` (the default); a preview list still does not sort (`sortable={false}` on the table).
- Form field messages: every built-in field (text, textarea, password, number, currency, price, phone, duration, range, rating, switch, checkbox, GDPR consent, select, multiselect, combobox, radio, reference, year, address, date / time, timestamp, rich text, map, geopoint, multi-input, file / document / image (single and multi), avatar, badge) renders the shared `FieldMessage` (`@donotdev/components`) instead of its own `<p>` / `⚠` markup with inline styles: one slot under the control, the error in place of the helper text, icon + text, announced (polite live region mounted from the first render; was `role="alert"` inserted with the message), no blank line without a message. Each control gets `aria-invalid` + `aria-describedby` to the slot from `fieldMessageAria` (select, combobox, multiselect, reference, address and range had none; file / document / image dropzones, `role="button"`, are described only). Field components take `error?: string` (the message) and `helperText?: string`; the controlled fields pass `fieldState.error?.message` as `error` (they passed it as `helperText` with a boolean `error`). Checkbox, GDPR consent and multi-input showed no error at all (a required consent failed with only the toast): they show it now.
- `useEntityForm` edit mode (so `EntityFormRenderer`): the record is the form's initial values from the first render, as create's defaults already were (React Hook Form `defaultValues`). It reached the form only through a `reset` in an effect, which never runs on the server: the server HTML had every field empty (a switch unchecked), and fields inside Suspense boundaries hydrated after that effect with the record, a hydration mismatch (shop `/compte`, `shippingSameAsBilling` switch) and an empty-then-filled flash. A record that arrives later (`loading`, async edit) is still applied by the reset.
- Field errors are visible: every form field coloured its error text and invalid border with `--destructive-foreground` (the text colour on a destructive background: white on the page). They use `--destructive`, like the auth fields.
- Entity form errors are translated: an emptied required field shows `crud:text.required` (was valibot's `Invalid type: Expected string but received null`), an invalid phone `crud:text.phone` (was English `Invalid phone number`), lengths, email, URL and dates their `crud:` messages, and a `validation.schema` message is a key of the entity namespace (`crud:text.invalid` when it has no translation). New keys `crud:text.phone`, `crud:text.invalid` (13 locales).
- Phone field: the dial code is never stored twice (`+33612345678`, `+33 6 12 34 56 78`, `0033612345678` → `+33 612345678`, were `+33 +33612345678` / `+33 33612345678`); separators are stripped (`06.12.34.56.78` → `+33 612345678`); the dial code alone (`+33`) stores `null`.

- `useCrudDoc` on Vite: while the record the URL names is not found, the document head carries `<meta name="robots" content="noindex">` (removed when the record shows up or the component unmounts), so crawlers do not index a client-rendered not-found state served with HTTP 200. The record the URL names: the current route (`matchRoute` from `@donotdev/core`, the AutoMetaTags matcher) declares the entity in its PageMeta (`meta.entity` = the collection read) and its `:param` value is the `id` read; a secondary read on the page (a missing brand on a valid product page) never noindexes it. Next adds nothing (entity pages answer a missing record with a real 404).
- `DateFilter` loads its calendar on demand (`LazyCalendar`, preloaded when the browser is idle and on trigger pointer-enter / focus): `react-day-picker` no longer ships up front with every list that has a date filter.
- `useCrudList` / `useCrudCardList` pass `translate` through: `translate: false` is honored (it was ignored, rows were translated anyway).
- `useCrudFilters`: render no longer writes the store (a page loaded with `f_*` params updated other components during render: React "Cannot update a component while rendering"). The first client render reads the URL, the mount effect seeds the store; server render and hydration show no filters.
- `EntityFilters`: chip remove and combobox clear buttons are translated (`form.remove`, `filter.clear`; were English "Remove" / "Clear").
- `EntityFilters`: a multi-select with values shows them (one value's label, `filters.selected` for several; was the placeholder). `filters.selected_other` added (fr, es, it, pt).
- One read path per shape: `get()` / `getDocQueryOptions` and `query()` / `getListQueryOptions` now share the access check, PII decryption and the server-render request adapter. Lists read through `useCrudList` / `useCrudCardList` previously returned PII ciphertext and skipped the access check. Subscriptions decrypt PII before writing the cache.
- `assertCanAccess` checks the adapter that performs the read (request-scoped on the server).
- Delete: a displayed document shows not-found (cache entry set to `null`, stale); an undisplayed entry is dropped. Previously `removeQueries` left it on screen.
- Failed delete no longer duplicates the row in cached lists.
- `EntityDisplayRenderer`: a read failure renders inline without a toast (same as lists) and is retried once (`retry: 1`); renders nothing when CRUD is unavailable instead of "not found".
- expo `FormFieldRenderer` / `EntityFormRenderer`: removed the deprecated `errors` prop (fields read `fieldState`).
